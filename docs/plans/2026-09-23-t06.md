# T06 Bounded Indexing Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task by task in the owner's D-drive project. Run the red test before each behavior change and the affected tests afterward.

**Goal:** Turn T05 staged source into fenced, reproducible, atomically published index generations.

**Architecture:** Add a source-continuation consumer, bounded parser/chunker and embedding provider behind ports, and PostgreSQL file/chunk/checkpoint storage. Publish generation, job and consumer completion in one transaction.

**Tech Stack:** Python 3.12, Tree-sitter, tiktoken, psycopg 3, pgvector, JetStream, pytest, strict mypy, Ruff.

**Spec:** `docs/plans/2026-09-23-t06-design.md`; `docs/spec.md`; ADR-005.

## Global constraints

- No source execution or secret-bearing file access; source bytes come only from verified T05 snapshots.
- Default mock/zero paid calls. Live embeddings need explicit local budget authorization.
- 600 target / 800 maximum chunk tokens, including metadata; overlap at most 80.
- At most 32 chunks and 20,000 tokens per embedding call; 384 dimensions.
- Two indexer slots; 60-second lease, 15-second heartbeat, five attempts and original job deadline.
- Python strict mypy, full annotations, no `Any` or blanket ignores. Immutable migrations 0001–0004.
