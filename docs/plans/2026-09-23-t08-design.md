# T08 pinned read-only agent design

T08 executes an accepted `agent.run.requested` event against the repository, generation and commit already pinned by T03 admission. The durable agent consumer checks the persisted event and fenced lease before every state change. It reads only complete indexed source and verified T05 blobs. Three in-process tools are exposed: `search_code`, `get_file`, and `get_repository_summary`. Model-supplied repository or generation IDs must match the server-owned run scope; unknown tools, invalid JSON and unsafe paths fail closed. Tool calls have a six-step durable ceiling, and results obey the 4,000-token/12,000-character, 200-line limits. No shell, repository execution, network fetch or write tool exists.

The first step retrieves at most 12 chunks and 8,000 evidence tokens with the shared T07 service, pinned to the run generation even if a newer generation becomes active. The provider loop makes at most six model attempts before the original 120-second deadline; instructions, tool schemas, history and evidence fit under 24,000 estimated input tokens, and output is capped at 2,000 tokens. The default mock provider makes no paid call and returns source-grounded or explicit insufficient-evidence results. Live mode is opt-in, uses the official AsyncOpenAI Responses API with `store=false`, `max_retries=0`, Luna low reasoning, validated function calls and a structured final object. Terra and Sol remain disabled until their documented evidence and operator gates are implemented and verified; no automatic upgrade occurs on missing evidence or provider errors.

Migration 0006 records every planned model call before dispatch, with model, conservative input estimate, maximum output, reserved USD, and eventual usage/state. The ledger and `agent_runs.attempts` are updated under the fenced lease and the shared admission lock. Each call reserves an input/output price with 20% margin under run USD 0.10, UTC-day USD 1.00, and deployment USD 4.00 ceilings; uncertain calls retain their full reservation. Price and key are operator supplied and freshness-checked before each paid call. Provider usage settles a reservation without increasing the reserved ceiling. The final validated `RunResult`, run status and durable consumer completion share one transaction before broker ACK. A crash or timeout cannot produce a second committed final result.

The three tools, durable bounded loop, budget ledger, and final result belong to T08. Ordered run events, SSE replay and CLI demonstration belong to T09. Tests cover forged scope and event, missing/changed active generation, exact file ranges, duplicate/redelivered events, sixth-step/attempt limits, cancellation, uncertain paid reservations, budget races, and no paid calls in the default profile. No live paid call is required for acceptance.
