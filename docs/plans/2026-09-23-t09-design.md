# T09 Design: Run Timeline, Replay, and Demonstration

## Outcome

An accepted run exposes ordered, durable progress over authenticated Server-Sent Events (SSE). A CLI can submit a public repository, wait for indexing, create a run, and print the final answer with immutable citations. The agent includes up to four source chunks from one statically resolved dependency hop before its first model call.

## Durable events

Migration 0007 adds `run_events` keyed by `(run_id, sequence)` and `sse_connections` with expiring connection leases. Events contain only the canonical `RunEvent` safe payload: start model, tool name and step, completion result, or safe failure code/message. No prompts, full tool output, credentials, or hidden reasoning are stored. A per-run row lock allocates strictly increasing sequence numbers. Starting and tool events require the owning consumer lease; terminal events share the result/failure and delivery-completion transaction. The deadline reconciler also writes a terminal failure event. Replayed delivery must not append a second terminal event.

## SSE

`GET /v1/runs/{run_id}/events` uses the existing bearer token and principal scope. `Last-Event-ID` is `<run UUID>:<sequence>`; mismatched, malformed, or future cursors are rejected. The endpoint replays persisted events after that sequence, polls for new events in bounded batches, sends heartbeats, and closes after a terminal event. A PostgreSQL lease table enforces two concurrent connections per principal and twenty deployment-wide, including across API replicas; each stream renews its lease and releases it on disconnect. Events remain readable for 24 hours after terminal state; older requests return `EVENT_CURSOR_EXPIRED`. Each stream has a finite lifetime and never buffers unbounded events in memory.

## One-hop expansion

The agent reads `index_files.dependencies` only for paths in its initial pinned search result, resolves Python and relative TypeScript imports only against manifest paths in the same generation, and loads at most four chunks from those direct targets. The existing twelve-chunk and 8,000-token cumulative evidence budgets apply to the combined context. Dynamic or external imports are skipped. Expansion is deterministic, best-effort, and cannot traverse to another generation or perform network/file-system lookup.

## CLI

The demonstration script uses the existing authenticated REST API and SSE; it does not import local source directly or bypass public GitHub admission. It has bounded polling and connection timeouts, generated idempotency keys, cursor reconnect, safe terminal errors, and concise citations. The default mock provider remains zero-cost. Tests use an in-process HTTP transport; no paid provider calls are part of T09 verification.
