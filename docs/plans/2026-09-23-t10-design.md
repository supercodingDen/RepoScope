# T10 Design: Operations Visibility and Fault Acceptance

## Goal

Make the existing finite admission and recovery behavior observable and demonstrably safe under dependency failures. Keep private metrics free of per-user identifiers and keep logs free of credentials, prompts, and source content.

## Instrumentation

Use the pinned `prometheus-client` already in the runtime. Add bounded-label HTTP request counts and latency for the public business routes, never raw URLs or UUIDs. The private management endpoint exposes dependency readiness, admission rejection counts, outbox publication outcomes, and worker delivery outcomes. A read-only PostgreSQL snapshot reports pending jobs/runs and unpublished outbox count; a periodic API-role sampler refreshes these gauges without changing business transactions. Metric collection failures must neither abort the API nor claim a healthy sample.

Structured logging emits only symbolic event names and validated safe fields. It never formats exception text. Request failures include request ID and safe error code; worker retry logs include event ID and safe error code. This preserves traceability without storing bodies, prompts, source text, connection URLs, or credentials.

## Backpressure and failure semantics

The database admission lock remains the authoritative global limit: up to 100 queued/running jobs and runs combined. Replays keep their original result even at capacity. JetStream bounds storage and in-flight messages; each worker has at most two slots. T10 adds explicit metrics and tests of these controls, without a parallel in-memory queue. Database outage maps to HTTP 503 and readiness loss; broker/Redis outage makes readiness 503 while liveness stays 200. Worker lease loss, cancellation, publication gaps, provider errors, and deadline reconciliation follow the existing durable transaction/fence path.

## Verification

Test metrics labels and monotonic outcomes without live providers, plus real PostgreSQL backlog gauges, admission saturation/replay, rollback, and worker crash gaps. Reuse the real NATS restart suite and pinned public source integration. Build a fault matrix with each tested boundary and identify Docker/Compose outage tests as unexecuted in this environment. Run the complete offline/native suites, Windows/Linux typing, lint/format, contracts, and redacted source-only secret scan before GitHub sync.
