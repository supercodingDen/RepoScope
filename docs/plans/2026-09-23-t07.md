# T07 Scoped Retrieval Implementation Plan

> **For agentic workers:** Implement in the owner's D-drive project. Use test-driven development for behavior changes, then run the full verification gates before GitHub synchronization.

**Goal:** Search complete, authorized T06 generations with hybrid ranking and immutable source citations.

**Architecture:** A typed retrieval service validates scope and query embedding; a PostgreSQL adapter performs exact/HNSW and FTS candidate selection. The public controller only authenticates, validates, delegates and serializes.

**Tech Stack:** Python 3.12, FastAPI, psycopg 3, pgvector, tiktoken, pytest, strict mypy, Ruff.

**Spec:** `docs/plans/2026-09-23-t07-design.md`; `docs/spec.md`; ADR-002.

## Global constraints

- Principal scope is server-owned; public search uses only the active complete generation.
- Same 384-dimensional embedding space, model and normalization for query and chunks.
- Vector and FTS each admit at most 50 candidates; RRF k=60; result cap 20.
- Query/provider timeout and paid budget rules remain in force.
- No repository code execution, no secret-bearing file reads or uploads, no paid calls in tests.
- Immutable migrations 0001-0005 and existing public contracts remain compatible.
