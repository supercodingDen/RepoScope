# T06 bounded indexing design

Status: implementation design for the owner's explicit T06 request, 2026-09-23.

## Outcome and scope

Consume T05's durable `repo.source.acquired` continuation and turn its pinned, verified source snapshot into a complete, queryable *generation*. Preserve source bytes, exact byte/line citations, deterministic chunk identities, parser/fallback reasons, static dependency hints and embedding-space identity. The public search API and agent execution remain T07/T08. Never execute imported source. The original job deadline and the T05 immutable pin remain authoritative.

## Architecture

Add a third durable JetStream consumer for `repo.source.acquired`. It shares T04's claim, lease, heartbeat, retry, fencing, completion-before-ACK and deadline machinery, but uses a separate indexing attempt counter so a successful fifth T05 attempt can still index. Extend the broker's reviewed T05 topology additively. Reject forged source continuations by matching the persisted outbox, job and manifest.

An `IndexHandler` reads one content-addressed blob at a time through the verified T05 store. It parses Python, TypeScript and TSX with pinned Tree-sitter grammars, labels syntax-error and unsupported-language fallback, and uses `cl100k_base` to enforce target 600 and hard 800 tokens including metadata; overlap never exceeds 80 tokens. It records byte offsets, original line ranges, symbol and static import hints. File parsing and disk reads run off the event loop with two total indexer slots. No whole-repository buffer is built.

The provider port accepts at most 32 chunks and 20,000 tokens per call. Default deterministic mock vectors are tagged `mock` and never counted as real quality evidence. The official OpenAI adapter requests `text-embedding-3-small`, `dimensions=384`, zero SDK retries and a finite timeout. Live mode requires a locally configured key, explicit paid-call opt-in, a current operator-verified price and a database budget reservation before each request. No live call is part of default tests or acceptance.

Migration 0005 adds scoped source-file, chunk, checkpoint and embedding-cache tables with generation/commit/owner constraints and 384-dimensional vectors. Every batch write checks the current consumer and job fence. A checkpoint means all chunks for that file have been written and validated; a crash can retry from the last complete file. Partial generations are invisible to retrieval. A final transaction checks all manifest files and embedding counts, rechecks the current requested generation and fence, marks the generation ready and job succeeded, swaps the repository active pointer, records consumer completion and only then ACKs. A superseded generation never becomes active. Empty eligible source sets are valid ready generations.

## Verification

Unit tests cover exact spans, token caps, AST/fallback labels, duplicate-content distinct citations, deterministic mock vectors and invalid provider vectors. Real PostgreSQL/NATS tests cover batch replay, fenced stale writes, crash gaps, ready publication, old active generation preservation, same-source reruns and deadline/retry outcomes. Fixtures and pinned public-source samples provide the 10K and 50K real-chunk memory/cardinality gates without paid model calls; report any gate that cannot actually run. Keep Docker/Linux runtime acceptance separate from native Windows evidence. Record the tested parser/tokenizer/embedding policy versions and source provenance.

## Decision record

The user already authorized completing T06 under the existing project specification and direct D-drive workflow. This design keeps live spending disabled by default, follows the accepted Python control plane and T05 handoff, and adds no public retrieval route before T07. GitHub synchronization occurs only after tests, review and a secret-safe file audit.
