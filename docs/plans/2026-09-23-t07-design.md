# T07 scoped retrieval design

T07 makes complete T06 generations searchable through one in-process service used by the public API and, later, the agent. A bearer-authenticated `POST /v1/search` accepts the existing `SearchRequest`; the server supplies the principal. The service resolves the repository's active ready generation and its embedding-space version before embedding the query. A missing or unfinished active generation returns `INDEX_NOT_READY`; an unknown or foreign repository returns `NOT_FOUND`. An empty ready generation returns an empty result.

The query uses the same provider, model, 384 dimensions and normalization as the stored chunks. Mock mode uses deterministic vectors and makes no paid call. Live mode requires the already defined paid opt-in, current price and durable daily budget reservation. A query with more than 800 `cl100k_base` tokens is rejected rather than silently truncated. Provider/space mismatch fails closed. The API composes a query provider only for its configured mode; it never uses the indexer's provider instance.

PostgreSQL performs scoped vector top-50 and code-friendly `simple` FTS top-50 over one pinned generation with identical language/path filters. The vector path is HNSW-eligible; when global ANN filtering returns fewer than 50 candidates, a scoped exact query supplies the complete top-50. A bounded exact variant is also available for baseline and recall checks. RRF uses `k=60`, stable tie-breaking by path and ordinal, and returns at most 20 matches. Path prefixes match either the exact path or descendants, with SQL wildcard characters treated literally. No query can select an arbitrary repository or generation through the public API.

Each result includes the pinned commit, repository/generation IDs, exact path and source lines, content and a deterministic chunk UUID derived from generation/path/ordinal. The index remains immutable after publication, so a concurrent new active generation cannot change a search already pinned to the old generation. T07 does not implement agent tool invocation or one-hop context expansion; those are T08/T09 workflows. Initial T07 measurements distinguish database-only exact/HNSW latency from end-to-end text search; 100K/32-client performance is a later roadmap gate and must not be claimed without running it.

Tests cover scope authorization, readiness, empty generations, mixed embedding spaces, literal path filters, language filters, deterministic RRF, citation stability, query token limits, and real PostgreSQL exact/HNSW/FTS retrieval. The default test profile makes no paid call.
