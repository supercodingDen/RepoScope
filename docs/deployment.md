# T15 production deployment runbook

There is **no hosted RepoScope deployment** yet. The complete operator procedure is [manual configuration](manual-configuration.md). `compose.yaml` remains the localhost development stack. `compose.production.yaml` and [Caddyfile](../deploy/Caddyfile) define a single-host HTTPS topology, but require owner-provided host, domain, secrets, and tested post-T15 images. The `v0.1.0` image archive was withdrawn before publication and would not support `scripts/launch_from_secrets.py`; build a reviewed current image set instead.

The proxy alone publishes TCP 80/443. PostgreSQL, Redis, NATS, migrations, and workers have no host ports. Docker Compose mounts three protected secret files into only the services that need them; the launcher passes credentials to the application process without storing them in Compose environment fields. The host administrator and Docker daemon remain trusted. API, indexer, and agent have an egress network for their documented external calls. The optional [live overlay](../compose.production.live.yaml) mounts a separate provider key only after explicit paid-call opt-in and verified price/budget settings.

Build first-party images from the exact green post-T15 commit, record their image IDs, keep a checksummed image archive, and pin the official Caddy image by manifest digest. Image IDs are local config digests, not registry manifest digests. Use `pull_policy: never` for first-party images. Record the source SHA, CI run, images, host specification, Compose hash, DNS name, deployment time, and endpoint. Render `docker compose -f compose.production.yaml config --quiet` before starting. Apply migrations with the one-shot service; take a backup before every schema-changing upgrade.

After startup, verify valid external HTTPS and 200 from `/healthz` and `/readyz`; verify a business route rejects missing authentication; verify only 80/443 are public. Run the pinned permitted-source demo against the public URL and record the job, citation commit, SSE reconnect/replay, and any live-provider result **separately** from mock output. Restart the project without deleting volumes and verify the same completed state and source citation. These are operator acceptance checks and have not been run here.

`scripts/backup.sh` pauses traffic/workers, dumps PostgreSQL, archives the quiescent source volume, hashes both files, and resumes. Copy its sensitive output to encrypted **off-host** storage and monitor backup age. Redis is disposable; JetStream delivery is reconciled from the authoritative PostgreSQL outbox/consumer state. Source blobs must accompany the database so `get_file` and pinned citations remain valid. `scripts/restore.sh` accepts only a fresh `reposcope-restore-*` project, checks hashes, restores database/source and privileges, and starts private services. Check jobs, outbox reconciliation, source citations, and recovery time in an isolated rehearsal. The scripts themselves and `pg_restore` success alone do not prove recovery.

The source cache lives in the backed-up `source-data` volume and is keyed by pinned commits; restore it with the database. The tokenizer cache is baked into the application image from frozen dependencies and can be reproduced from the reviewed source/build. OpenAI models are remote; no model weights or local model cache are claimed. Keep these distinct when estimating disk and recovery time.

For rollback, retain the previous compatible image archive and a pre-migration database backup. Rehearse the old application against its matching schema in an isolated project; never assume a schema downgrade. `scripts/check_disk.sh` fails above 80% usage or below 10 GiB free; connect it and bounded Compose logs to actual alerts. This is a single-host deployment, not high availability.

For current local operation, follow [development](development.md) and [recovery](failure-modes.md). [Project status](project-status.md) and [acceptance](acceptance.md) record open gates. Docker's [Compose secrets](https://docs.docker.com/reference/compose-file/secrets/) grant file mounts per service; Caddy's [automatic HTTPS](https://caddyserver.com/docs/automatic-https) requires correct public DNS and reachable 80/443. The T12 HNSW migration can take several minutes on a 100K-chunk database; pause indexing writes and back up first.
