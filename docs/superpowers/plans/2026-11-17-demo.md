# Interactive Recorded Demo Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task. The owner approved execution in the current VSCode project.

**Goal:** Deliver a reproducible static visual demo for AI Engineer portfolio review.

**Architecture:** A Python allowlist exporter captures public API search/results and SSE events from a disposable mock-only stack. A React frontend reads a validated, versioned recording, and builds static files for GitHub Pages. Public backend hosting and paid-provider evaluation stay separate.

**Tech Stack:** Python 3.12, Pydantic, httpx; React, TypeScript, Vite, ESLint, Playwright, npm lockfile.

**Spec:** ../specs/2026-11-17-demo-design.md

## Global Constraints

- English identifiers, docs and UI; strict types and validation of external values.
- Zero paid calls; no dotenv access, browser tokens, arbitrary capture URLs, or new public API.
- Preserve pre-existing migration edits; only explicitly reviewed demo files enter the PR.
- Only frontend dist is uploaded to Pages; current main protection and required checks remain in force.

## Review Focus

- Malformed, cross-revision, or secret-bearing exports must fail before publication (Task 1).
- Replayed events must continue after the cursor without duplicates (Task 1).
- Switching cases during playback must reset selected evidence and timers (Task 2).
- Citation URLs and source contents must be inert text from the pinned public source (Tasks 1-2).
- Project-path deployment, failed data loading, small screens, and keyboard navigation must remain usable (Tasks 2-3).

Interfaces: capture produces schema_version=1, provenance, cases (search, result, events, resume proof), and benchmark summaries. Frontend consumes exactly this file. Canonical HTTP contracts remain unchanged.
