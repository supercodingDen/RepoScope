# T08 read-only agent

An accepted run pins its repository, completed index generation and commit. The agent consumer rechecks that persisted scope under its delivery lease, then searches only that generation. The three callable tools are `search_code`, `get_file` and `get_repository_summary`. They reject foreign repository or generation IDs. File reads use only verified immutable blobs listed in the source manifest; imported source is never executed. A search result has at most 12 chunks and 4,000 text tokens/12,000 text characters; a file request has at most 200 lines and a 4,000-token/12,000-character response.

Default `PROVIDER_MODE=mock` makes no model or embedding API calls. It produces a simple labeled excerpt and citation from the first retrieved chunk, or an insufficient-evidence result if no chunks match. This demonstrates the workflow and is not a claim of answer quality. The final result is committed with consumer completion before the broker ACK. T09 owns durable run-event replay and SSE; those are not part of this milestone.

Live mode uses the official OpenAI Python SDK Responses API with the three local function schemas and a JSON final answer. Luna is the sole enabled route. Terra and Sol escalation remain disabled. To enable paid calls in the agent process, set `PROVIDER_MODE=openai`, `ALLOW_PAID_API_CALLS=true`, a local `OPENAI_API_KEY`, the existing embedding budget/price settings, and `AGENT_INPUT_PRICE_PER_MILLION_USD`, `AGENT_OUTPUT_PRICE_PER_MILLION_USD`, `AGENT_PRICE_VERIFIED_DATE`. The verified dates must be no older than seven days. Recheck current provider prices before setting them. The application does not ship paid credentials or prices.

Every provider attempt commits a fenced, worst-case reservation first, including a 20% margin and the maximum 2,000 output tokens. A run has at most six model attempts and six tool steps, at most 24,000 estimated input tokens per call, and the original 120-second run deadline. Reservations keep timeout/unknown-usage calls charged conservatively. PostgreSQL serializes agent and embedding reservations through the shared admission lock; both count toward the UTC-day and deployment ceilings. Application defaults are USD 0.10 per run, 1.00 per UTC day, and 4.00 per deployment. No SDK automatic retry is enabled.

The local Windows acceptance uses an isolated PostgreSQL 17/pgvector 0.8.6 cluster and simulated provider responses. No live paid call was made. Docker/Compose smoke acceptance and live-model quality remain separate gates.
