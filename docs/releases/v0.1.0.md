# RepoScope v0.1.0 pre-release

This is a source and container-artifact pre-release of RepoScope's local, single-host demonstration. It includes durable import and agent jobs, pinned public GitHub source acquisition, hybrid code search, three read-only agent tools, replayable SSE, a mock-only small-repository demo, and the T12 raw performance evidence. The source is Apache-2.0; see `LICENSE`, `NOTICE`, and `docs/third-party-notices.md`.

The release assets include a gzip-compressed Docker image archive for the API/worker, PostgreSQL/pgvector, and NATS images; CycloneDX SBOMs for those images; `release-metadata.json` with the exact source commit/tree and image IDs; and `SHA256SUMS` for the other five assets. Docker image IDs and archive checksums identify these exact builds. The pinned Redis upstream digest is recorded in `docs/runtime-images.json`. No package registry or hosted endpoint is claimed by this release. Load an archive image only after checking `SHA256SUMS` and reviewing the source and notices.

After downloading all six assets into one directory, run `sha256sum --check SHA256SUMS`; then load the verified archive with `gzip -dc reposcope-v0.1.0-images.tar.gz | docker load`. Image IDs in the metadata are local Docker config digests, not registry manifest digests. The archive checksum identifies the distributed image set. The release does not publish a GHCR image.

The documented [small demo](../demo.md) uses mock providers, a pinned public repository revision, and no paid calls. Live-provider quality and latency were not verified. The T12 32-client search p95 target of 100 ms and non-search p95 target of 30 ms were missed in local measurements; semantic relevance, full-agent overhead, and single-job 100K ingestion also remain open. This release does not claim complete performance acceptance, high availability, HTTPS hosting, backup/restore, or rollback proof. See [status](../project-status.md), [performance](../t12-performance.md), and [deployment prerequisites](../deployment.md).

For a fresh source checkout, install Python 3.12.14, uv 0.12.11, and Docker Compose; run `uv sync --frozen --all-groups`, configure only local random secrets in `.env`, start the mock stack, then follow the pinned demo. The release workflow checks the same commit with remote CI and a disposable fresh-checkout demo before creating the version tag.
