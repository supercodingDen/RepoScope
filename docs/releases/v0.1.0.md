# RepoScope v0.1.0 pre-release

This is a source and historical SBOM pre-release of RepoScope's local, single-host demonstration. It includes durable import and agent jobs, pinned public GitHub source acquisition, hybrid code search, three read-only agent tools, replayable SSE, a mock-only small-repository demo, and the T12 raw performance evidence. The source is Apache-2.0; see `LICENSE`, `NOTICE`, and `docs/third-party-notices.md`.

The original release had six assets. Before public visibility, an independent layer scan found a Debian-generated `ssl-cert-snakeoil.key` private key in the PostgreSQL image archive. The archive, its now-obsolete `SHA256SUMS`, and `release-metadata.json` were withdrawn while the repository was still private. The pre-release now retains only three historical CycloneDX SBOMs. They are reference records, not deployable images. The pinned Redis upstream digest is recorded in `docs/runtime-images.json`. No package registry or hosted endpoint is claimed by this release.

The repository's [publication asset audit](../../.github/workflows/publication-asset-audit.yml) verifies the three retained SBOM digests and scans their bytes for recognized secrets. Build current images from reviewed source when a host is available; do not deploy the withdrawn v0.1.0 image set. The release does not publish a GHCR image.

The historical runtime image carried the project's license, notice, and third-party notes. The NATS image carried the Apache-2.0 license text and [NATS attribution](../nats-notice.txt). The original release job verified these files before archiving the images; that archive is no longer distributed.

The documented [small demo](../demo.md) uses mock providers, a pinned public repository revision, and no paid calls. Live-provider quality and latency were not verified. The T12 32-client search p95 target of 100 ms and non-search p95 target of 30 ms were missed in local measurements; semantic relevance, full-agent overhead, and single-job 100K ingestion also remain open. This release does not claim complete performance acceptance, high availability, HTTPS hosting, backup/restore, or rollback proof. See [status](../project-status.md), [performance](../t12-performance.md), and [deployment prerequisites](../deployment.md).

For a fresh source checkout, install Python 3.12.14, uv 0.12.11, and Docker Compose; run `uv sync --frozen --all-groups`, configure only local random secrets in `.env`, start the mock stack, then follow the pinned demo. The release workflow checks the same commit with remote CI and a disposable fresh-checkout demo before creating the version tag.
